AUTHENTICATION AND ROLE-BASED ACCESS ACTIVITY

OBJECTIVE

Build a login system that validates accounts using MongoDB.

The application must distinguish between:

user
admin

Normal users must go to the User Dashboard.

Administrators must go to the Admin Dashboard.

All account data used for validation must come from MongoDB.


PART 1 - START MONGODB

1. Make sure MongoDB is running.

2. Open Terminal or Command Prompt.

3. Run:

mongosh

4. Switch to:

use coffee_auth


PART 2 - INSTALL PACKAGES

5. Extract the ZIP.

6. Open a terminal in the project folder.

7. Run:

python -m pip install -r requirements.txt


PART 3 - CREATE TEST USERS

8. Run:

python seed_users.py

This creates two MongoDB accounts.

USER

Email:
user@coffee.local

Password:
User123!

Role:
user


ADMIN

Email:
admin@coffee.local

Password:
Admin123!

Role:
admin


9. Verify in mongosh:

use coffee_auth

db.users.find(
    {},
    {
        password_hash: 0
    }
)


PART 4 - DATABASE CONNECTION

Open app.py.

Complete TODO 2.

Connect to:

mongodb://localhost:27017/

Database:
coffee_auth

Collection:
users


PART 5 - LOGIN API

Complete TODO 3.

Create:

POST /api/login

The API must:

- receive email and password
- find the account in MongoDB
- verify the account is active
- validate the password using check_password_hash()
- create a Flask session
- store name, email, role, and user ID in the session
- return the role to the browser


PART 6 - FRONTEND LOGIN

Open login.js.

Complete TODO 1.

The webpage must:

- read email and password
- POST JSON to /api/login
- read the returned role

If role is:

user

go to:

/user

If role is:

admin

go to:

/admin


PART 7 - CURRENT USER

Complete TODO 4.

Create:

GET /api/me

If no session exists:

return 401

If logged in:

return name, email, and role.


PART 8 - PROTECT USER PAGE

Complete TODO 5.

Create:

GET /user

The account must be logged in.


PART 9 - PROTECT ADMIN PAGE

Complete TODO 6.

Create:

GET /admin

Only an account whose MongoDB role is:

admin

may access it.

A normal user must receive:

403 Forbidden


PART 10 - LOGOUT

Complete TODO 7.

Create:

POST /api/logout

Clear the session.


PART 11 - RUN AND TEST

Run:

python app.py

Open:

http://localhost:5000


TEST 1

Login as:

user@coffee.local
User123!

Expected:

User Dashboard


TEST 2

Logout and login as:

admin@coffee.local
Admin123!

Expected:

Admin Dashboard


TEST 3

Login as the normal user.

Then manually open:

http://localhost:5000/admin

Expected:

403 Forbidden


TEST 4

Use a wrong password.

Expected:

Login fails.


FINAL CONCEPTS

AUTHENTICATION

Who are you?

Login form
-> POST /api/login
-> MongoDB
-> password validation
-> session


AUTHORIZATION

What are you allowed to access?

session
-> role
-> user page or admin page
